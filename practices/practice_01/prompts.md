## Master Prompt v1

Соберите здесь контракт второго запуска. Не копируйте все документы целиком — ставьте ссылки на файлы и переносите только необходимый для задачи контекст.

### 1. Цель и роль

- Цель: повысить доказательность и пригодность ответа AI-помощника при ревью diff
- Роль AI: консультант code review, возвращающий summary, до 3 подтверждённых рисков и список проверок

### 2. Входы и источники

- Обязательный вход: строка diff TRAINING_PR.diff
- Разрешённые файлы и источники: CASE.md, README.md, context.md (только относящиеся к задаче правила)
- Context Pack — факты, правила, примеры и ограничения: см. context.md раздел «Context Pack для первого рабочего сценария»

### 3. Задача и артефакты

- Что сделать: принять diff, отредактировать секреты, сформировать prompt с Context Pack, вызвать LLM с таймаутом и вернуть структурированный результат
- Что вернуть: JSON/объект OUT‑1: summary; risks[≤3] с file, line, evidence, risk; checks[]

### 4. Формат результата

- Структура ответа: OUT‑1 — поля summary, risks (≤3 элементов), checks; в risks: file, line, evidence, risk
- Ограничения объёма: не включать более 3 рисков; избегать лишнего текста; ссылки на конкретные строки

### 5. Полномочия и запреты

- Разрешено: анализировать diff, ссылаться на строки, предлагать проверки
- Запрещено: approve, merge, изменять код; отправлять секреты; использовать внешние источники

### 6. Рабочий процесс и остановка

- Шаги:
  1. Проверить длину diff (≤20 000); вернуть 413 при превышении
  2. Редактировать секреты: заменить токены/пароли/ключи на [REDACTED]
  3. Сформировать prompt с Context Pack и правилами
  4. Вызвать LLM с таймаутом 10 c; при ошибке вернуть контролируемый ответ
  5. Сформировать OUT‑1 с подтверждёнными рисками (QA‑1)
- Когда остановиться и запросить человека: если evidence не найдено или контекст недостаточен

### 7. Проверки и evidence

- Как проверять утверждения: каждый риск должен ссылаться на строку diff или правило; без этого не включать
- Какое evidence сохранить: file, line, цитата evidence из diff; описать проверку, которую можно повторить

### 8. Definition of Done

- Задача закончена, когда: возвращён OUT‑1; рисков ≤3 и каждый подтверждён; соблюдены SEC‑1, API‑1, REL‑1, OBS‑1; указаны воспроизводимые проверки

## Сравнение двух запусков

| Проверка | Zero-shot | С master prompt | Вывод команды |
|---|---|---|---|
| Есть ссылка на файл или строку | Часто отсутствует | Обязательна для каждого риска | Улучшение: +ссылки |
| Вывод подтверждён diff или правилом | Нередко предположения | QA-1: только с evidence | Повысили доказательность |
| Соблюдены границы AI | Иногда выходит за SCOPE | SCOPE-1 соблюдается | Сдержали полномочия |
| Есть воспроизводимая проверка | Отсутствует | Для каждого риска указана проверка | Повысили воспроизводимость |
