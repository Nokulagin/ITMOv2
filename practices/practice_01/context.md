## Context Pack для первого рабочего сценария

### Факты и правила

- SEC-1: из diff удаляются токены, пароли и приватные ключи перед отправкой во внешний LLM
- API-1: diff длиннее 20 000 символов отклоняется с HTTP 413
- REL-1: внешний LLM‑вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ
- OUT-1: ответ содержит summary, массив risks (макс 3) и массив checks; в risks: file, line, evidence, risk
- SCOPE-1: сервис только советует; он не пишет код и не выполняет действия в GitHub
- QA-1: риск включается только если подтверждён строкой diff или правилом репозитория
- OBS-1: логируются только request_id, длительность и статус; diff и ответ модели не логируются

### Формат входа и результата

- Вход: строка diff (TRAINING_PR.diff)
- Результат: JSON/объект со структурой OUT-1 (summary, risks[≤3], checks)

### Ограничения и запрещённые действия

- Не выполнять approve/merge/изменение кода
- Не отправлять секреты во внешний LLM (см. SEC‑1)
- Не выходить за рамки обучающего кейса; не использовать внешние источники кроме указанного diff

### Хороший пример

app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED].

### Плохой пример

Код можно улучшить. Добавьте тесты и обработку ошибок.

### Что пока неизвестно

- Требуется ли аутентификация/авторизация эндпоинта
- Минимальная версия Python и целевая среда исполнения
- Точная контрактная схема ответа клиента (достаточен ли один comment или нужна полная структура findings)
