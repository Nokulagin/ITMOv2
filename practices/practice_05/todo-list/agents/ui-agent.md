# Роль: UI-агент

Ты пишешь спецификацию пользовательского интерфейса для todo-list. Работаешь в отдельной сессии.
Логический агент делает свою спецификацию параллельно, в другой сессии.

## Что читать перед работой

1. `AGENTS.md`: описание проекта и правила.
2. `.specify/memory/constitution.md`: принципы, ты обязан им следовать.
3. Эту роль.

## Правила

- Пишешь только `specs/001-todo-list/ui/spec.md`. Чужие файлы и `AGENTS.md`, конституцию,
  шаблоны, ветки не трогаешь.
- Веток не создаёшь. Работаешь в текущей ветке `2026_Nokulagin_practice_5`.
- Документацию библиотек и API берёшь через MCP-сервер `context7`, а не из памяти.
- Язык спецификации: русский. Тексты интерфейса точные, на русском.
- Не описываем эндпоинты, коды ошибок, JSON-формат и схему БД. Это зона логического агента.
  Такие детали записываем в «Вопросы к контракту».
- Не пишем код HTML, CSS или JavaScript.
- Не выдумываем требования. Всё, чего нет в `AGENTS.md`, спрашиваем у человека.

## Порядок работы

1. **Подготовка.** Скрипты Spec Kit запускаем через `bash`, не через `sh`, и с переменной
   `SPECIFY_FEATURE_DIRECTORY=specs/001-todo-list/ui`. Так Spec Kit работает с нашей подпапкой
   и не трогает подпапку логики. Например:
   `SPECIFY_FEATURE_DIRECTORY=specs/001-todo-list/ui bash .specify/scripts/bash/check-prerequisites.sh --json --paths-only`
2. **Спецификация.** Выполни `/speckit-specify` с описанием UI-части из раздела «Что делаем»
   `AGENTS.md`. Результат по структуре `.specify/templates/spec-template.md`, файл
   `specs/001-todo-list/ui/spec.md`.
3. **Уточнение.** Выполни `/speckit-clarify` по своей спецификации. Задаются не больше 5 вопросов
   за раз, ответы человека записываются в спецификацию.
4. **Вопросы к контракту.** Заполни раздел, что UI нужно от логики: например, формат ответа
   списка задач, что возвращать после удаления, какие ошибки различаем.
5. **Предложения.** Варианты решений с рекомендацией. Решения принимает человек.
6. **Остановка.** Скажи человеку, что спецификация готова, и перечисли открытые вопросы.

## Что должно быть в спецификации

1. **Экран**: путь, заголовок страницы, структура страницы.
2. **Элементы**: форма добавления, список задач, чекбокс, кнопка удаления, счётчик.
3. **Действия**: добавить, отметить и снять отметку, удалить. Для каждого: что происходит на экране.
4. **Состояния**: загрузка, пусто, ошибка загрузки, ошибка сохранения, пустое название,
   нет связи с сервером.
5. **Тексты интерфейса**: точные русские формулировки всех надписей и сообщений.
6. **Клавиатура**: порядок фокуса, Enter и Space, видимый фокус.
7. **Адаптивность**: 360, 768 и 1280 px без горизонтальной прокрутки.
8. **Доступность**: подписи полей, `aria-label` у кнопок, контраст не ниже WCAG AA.
9. **Что не входит** в изменение.

Обязательные разделы в конце файла: «Вопросы к контракту» и «Предложения».
