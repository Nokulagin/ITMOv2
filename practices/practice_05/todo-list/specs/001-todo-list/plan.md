## Summary

Одна страница со списком задач: добавить, отметить и снять отметку, удалить, счётчик «Выполнено: N из M». Задачи хранятся в SQLite-файле `data/todos.db`. Сервер на стандартной библиотеке Python отдаёт страницу и JSON-API `/api/todos`. Страница на чистом HTML, CSS и JavaScript вызывает API. Всё, что касается формата данных, ошибок и порядка списка, берётся из контракта.

## Technical Context

**Language/Version**: Python 3 (в документации context7 описанные модули одинаковы для 3.9–3.13; версия на машине разработчика определяется при первом запуске)

**Primary Dependencies**: нет. Только стандартная библиотека: `http.server`, `sqlite3`, `json`, `unittest`, `contextlib`, `pathlib`

**Storage**: SQLite-файл `data/todos.db` от корня проекта. Папка создаётся при старте. Таблица создаётся `CREATE TABLE IF NOT EXISTS`, `id` с `AUTOINCREMENT`

**Testing**: `unittest` для логики и API (тест-кейсы 1–27 из `logic/spec.md`). UI: ручной чек-лист по `ui/spec.md` (клавиатура, 360/768/1280 px, контраст, тексты)

**Target Platform**: современный браузер на десктопе и телефоне; сервер на локальной машине разработчика

**Project Type**: web-приложение из одной страницы и JSON-API на одном origin

**Performance Goals**: не задаются. Учебный проект, один пользователь, один запрос за раз (`HTTPServer` синхронный)

**Constraints**: без pip, без фреймворков, без сборки, без CDN. Лимит тела запроса 4096 байт. Название 1–200 кодовых точек Unicode после обрезки. Тексты интерфейса на русском

**Scale/Scope**: один список, одна страница, четыре операции

## Research

Проверено через context7 (`/python/cpython`), 2026-10-20:

- `http.server.HTTPServer` обрабатывает запросы синхронно, по одному в главном потоке. Это соответствует «однопоточному серверу» из логики. `ThreadingHTTPServer` не используем.
- `sqlite3`: соединение как контекстный менеджер (`with conn:`) коммитит или откатывает транзакцию, но не закрывает соединение. Поэтому соединение оборачиваем в `contextlib.closing`. Так соответствует правилу «соединение открывается и закрывается на каждую операцию».
- `check_same_thread` оставляем по умолчанию: соединение используется только в потоке сервера.

### Source Code (repository root)

```text
todo-list/
├── app.py               # запуск сервера, маршрутизация, раздача страницы и статики
├── todos.py             # логика: валидация, хранилище SQLite, операции над задачами
├── static/
│   ├── index.html       # единственная страница
│   ├── styles.css       # стили, mobile-first
│   └── script.js        # вызовы API, обновление списка и состояний
├── tests/
│   ├── test_todos.py    # тест-кейсы логики (unittest)
│   └── test_app.py      # тест-кейсы HTTP-API (unittest, временная база)
└── data/                # создаётся при старте; в git не попадает
    └── todos.db
```

**Structure Decision**: два слоя на бэкенде. `todos.py` не знает про HTTP и отвечает за правила и SQL. `app.py` знает про HTTP: разбирает тело, проверяет лимит 4096 байт, сопоставляет исключения с кодами из контракта. Такое разделение нужно, чтобы тесты логики не поднимали сервер. Статика лежит в `static/`, чтобы страница и серверный код не смешивались.
