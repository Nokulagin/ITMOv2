# Data Model: Список задач (UI)

**Feature**: `specs/001-todo-list/ui/spec.md` | **Date**: 2026-10-20

UI ничего не хранит постоянно: хранилище и схема БД описаны в логической спецификации. Здесь только то, что держит страница в памяти во время работы.

## Task (представление задачи в UI)

| Поле | Тип | Источник | Примечание |
|---|---|---|---|
| `id` | целое число больше 0 | контракт, раздел 2 | Нужен для отметки и удаления |
| `title` | строка | логика | Название; UI показывает как есть |
| `done` | логическое значение | логика | Признак выполнения |

Порядок в списке задаёт логика: новые задачи сверху (решено: Q3, ответ B). UI не сортирует.

## Page state

| Поле | Тип | Смысл |
|---|---|---|
| `tasks` | список Task | Текущий список, как отдала логика |
| `status` | `loading` / `ready` / `load-error` | Состояние загрузки |
| `pending` | логическое значение | Идёт ли запрос добавления (кнопка заблокирована, решено: Q2) |
| `message` | строка или пусто | Текст сообщения из раздела «Состояния» |
| `messageField` | `title` / `list` / пусто | Где показывать сообщение: под полем или в области списка |

## Вычисляемые значения

- `doneCount` = число задач с `done = true`.
- `totalCount` = длина `tasks`.
- Счётчик «Выполнено: {doneCount} из {totalCount}» показывается, только если `totalCount > 0` (решено по рекомендации, см. спецификацию).

## Правила валидации на стороне UI

- Название обрезается по краям до отправки (К7).
- Пустое название (после обрезки) не отправляется: сообщение «Введите название задачи.».
- Длина: по контракту (раздел 6) считаются кодовые точки Unicode после обрезки. Расхождение с ответом человека на Q3 (видимые символы) открыто, см. `plan.md`, «Открытые решения».

## Переходы состояний

- `loading` → `ready`: список получен.
- `loading` → `load-error`: ответ с ошибкой при загрузке.
- `ready` + добавление: `pending = true` → при `201` поле очищается и список запрашивается заново (`GET`), `pending = false`; при ошибке `pending = false`, `message` выставляется, поле не очищается.
- `ready` + отметка или удаление: при `200` или `204` список запрашивается заново; при ошибке флажок возвращается, `message` выставляется. При `404` сообщение «Задача не найдена. Обновите страницу.» и список запрашивается заново (контракт, раздел 5).
