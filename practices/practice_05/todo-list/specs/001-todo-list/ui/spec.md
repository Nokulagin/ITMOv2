## User Scenarios & Testing *(mandatory)*

Тексты, отмеченные как *(предложено)*, придуманы UI-агентом. Тексты в разделе «Тексты интерфейса» ещё не утверждены человеком.

### User Story 1 - Добавить задачу (Priority: P1)

Пользователь вводит название и нажимает «Добавить» или Enter. Задача появляется в начале списка, поле очищается, фокус остаётся в поле (порядок решён: Q3, ответ B).

**Why this priority**: без добавления список бесполезен; это основной сценарий.

**Independent Test**: открыть страницу, добавить задачу «Купить молоко», увидеть её в списке после перезагрузки страницы.

**Acceptance Scenarios**:

1. **Given** список пуст, **When** пользователь вводит «Купить молоко» и нажимает «Добавить», **Then** в списке появляется одна задача «Купить молоко» с невыбранным чекбоксом, поле очищено, счётчик обновлён.
2. **Given** в поле пробелы или ничего, **When** пользователь нажимает «Добавить», **Then** задача не создаётся, под полем появляется «Введите название задачи.», фокус остаётся в поле.
3. **Given** в поле 201 символ, **When** пользователь нажимает «Добавить», **Then** задача не создаётся, появляется «Название не длиннее 200 символов.».
4. **Given** в поле 200 символов, **When** пользователь нажимает «Добавить», **Then** задача создаётся.
5. **Given** в поле «  Купить хлеб  » (с пробелами по краям), **When** пользователь нажимает «Добавить», **Then** задача сохраняется как «Купить хлеб» без пробелов по краям.

### User Story 2 - Отметить и снять отметку выполнения (Priority: P2)

Пользователь ставит или снимает отметку у задачи. Состояние сохраняется, счётчик обновляется.

**Why this priority**: отметка выполнения — второй по важности сценарий; без неё задача не меняет состояние.

**Independent Test**: отметить задачу, перезагрузить страницу, увидеть отметку на месте.

**Acceptance Scenarios**:

1. **Given** невыполненная задача, **When** пользователь ставит отметку, **Then** отметка стоит, название зачёркнуто, счётчик «выполнено» увеличился на 1.
2. **Given** выполненная задача, **When** пользователь снимает отметку, **Then** отметка снята, зачёркивание убрано, счётчик «выполнено» уменьшился на 1.
3. **Given** пользователь отметил задачу, **When** страница перезагружается, **Then** задача остаётся выполненной.

### User Story 3 - Удалить задачу (Priority: P3)

Пользователь нажимает «Удалить» у задачи. Задача исчезает из списка.

**Why this priority**: удаление нужно, но без него список остаётся рабочим; можно обойтись отметкой.

**Independent Test**: удалить задачу, перезагрузить страницу, убедиться, что её нет.

**Acceptance Scenarios**:

1. **Given** в списке есть задача, **When** пользователь нажимает «Удалить» у неё, **Then** задача исчезает из списка, счётчик обновлён. Подтверждение не запрашивается (решено: Q1, ответ A).
2. **Given** в списке одна задача, **When** её удаляют, **Then** список показывает пустое состояние.

### User Story 4 - Загрузка списка при открытии страницы (Priority: P1)

**Why this priority**: без загрузки пользователь не увидит ранее сохранённые задачи.

**Independent Test**: добавить задачи, перезагрузить страницу, увидеть те же задачи.

**Acceptance Scenarios**:

1. **Given** в хранилище есть задачи, **When** страница открывается, **Then** пока список грузится, показывается «Загрузка…»; затем задачи отображаются, новые сверху (порядок из контракта).
2. **Given** в хранилище нет задач, **When** страница открывается, **Then** показывается пустое состояние.
3. **Given** сервер недоступен, **When** страница открывается, **Then** показывается ошибка загрузки (см. раздел «Состояния»).

### Edge Cases

- Название из 200 символов из кириллицы или эмодзи: длина считается в кодовых точках Unicode, как в логике (Q3, пересмотрено). Эмодзи из нескольких кодовых точек, например семья или флаг, считается как несколько символов.
- Два быстрых клика по «Добавить»: создаётся одна задача, а не две; кнопка блокируется на время запроса (решено: Q2).
- Задача с длинным названием без пробелов: переносится внутри строки, кнопка «Удалить» не уезжает за экран.
- Задачу отметили или удалили в другой вкладке: UI показывает «Задача не найдена. Обновите страницу.» и перезагружает список (решено: К6).
- Сервер остановлен, страница открыта: при следующем действии показывается «Нет связи с сервером».
- Счётчик при пустом списке: скрыт (Q2, по рекомендации).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Страница показывает список задач, загруженный при открытии.
- **FR-002**: Пользователь может добавить задачу, введя название от 1 до 200 кодовых точек Unicode (после обрезки пробелов по краям).
- **FR-003**: Пустое название и название длиннее 200 символов не отправляются на сервер; пользователь видит сообщение рядом с полем.
- **FR-004**: Пользователь может отметить задачу выполненной и снять отметку.
- **FR-005**: Пользователь может удалить задачу кнопкой «Удалить».
- **FR-006**: Счётчик показывает общее число задач и число выполненных; при пустом списке скрыт.
- **FR-007**: Все состояния из раздела «Состояния» имеют видимый текст и не требуют перезагрузки для повторной попытки.
- **FR-008**: Все операции доступны с клавиатуры, фокус виден.
- **FR-009**: Страница работает без горизонтальной прокрутки при 360, 768 и 1280 px.
- **FR-010**: Все видимые тексты на русском, из раздела «Тексты интерфейса».

### Key Entities

- **Задача**: название и признак выполнения. Структура, ограничения и идентификатор определяются контрактом (`specs/001-todo-list/contract.md`).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Добавление задачи занимает одно действие: ввод и Enter, без мыши.
- **SC-002**: Все три операции (добавить, отметить, удалить) проходятся только с клавиатуры в ручном чек-листе без ошибок.
- **SC-003**: На 360, 768 и 1280 px нет горизонтальной прокрутки и обрезанного текста кнопок.
- **SC-004**: Все тексты из раздела «Тексты интерфейса» совпадают с выведенными на экране дословно.
- **SC-005**: Контраст проверен инструментом, не на глаз, и не ниже WCAG AA.

## Assumptions

- Пользователь работает в современном браузере с поддержкой стандартных элементов форм.
- Страница и данные открываются из одного места, поэтому пользователь не настраивает адрес сервера.
- В проекте один список; пользователей и входа нет.
- Хранение данных (способ и место) описано в логической спецификации и контракте, а не здесь.
- Проверка UI ручная по этому файлу (клавиатура, адаптивность, контраст), автоматического UI-теста нет (конституция, принцип V).

- **Структура** сверху вниз: заголовок страницы; форма добавления; счётчик; список задач. Пустое состояние и сообщения о состояниях выводятся в области списка.

## Состояния

| Состояние | Когда | Что видит пользователь *(предложено)* |
|---|---|---|
| Загрузка | Список запрашивается при открытии | «Загрузка…» вместо списка; форма доступна |
| Пусто | После успешной загрузки задач нет | «Задач пока нет. Добавьте первую.» |
| Ошибка загрузки | Список не получен (ответ с ошибкой) | «Не удалось загрузить список. Обновите страницу.» |
| Ошибка сохранения | Добавление, отметка или удаление не сохранились | «Не удалось сохранить изменения. Попробуйте ещё раз.» |
| Пустое название | Поле пустое или только из пробелов | «Введите название задачи.» под полем |
| Слишком длинное название | Больше 200 символов | «Название не длиннее 200 символов.» под полем |
| Нет связи с сервером | Запрос не дошёл до сервера | «Нет связи с сервером. Проверьте подключение и попробуйте ещё раз.» |
| Задача не найдена | Отметили или удалили задачу, которой уже нет | «Задача не найдена. Обновите страницу.» *(решено, см. К6)* |

Правила:

- При ошибке сохранения и при «Нет связи» введённый текст в поле добавления не очищается.
- При ошибке отметки или удаления задача остаётся в прежнем состоянии, флажок возвращается в прежнее положение.
- Пока запрос добавления выполняется, кнопка «Добавить» заблокирована, повторный клик не создаёт дубль (решено: Q2, ответ A).
- Поле названия не ограничивает ввод (нет `maxlength`). При длине больше 200 кодовых точек показывается «Название не длиннее 200 символов.» (сценарий 3). Сервер проверяет длину тоже.
- Сопоставление ответов сервера с состояниями описано в `specs/001-todo-list/contract.md`, раздел 5.
- После каждой успешной операции список запрашивается заново (решение логики, см. контракт).
- При ответе 404 на отметку или удаление UI показывает «Задача не найдена. Обновите страницу.» и перезагружает список.

## Клавиатура

- Порядок фокуса: поле добавления → «Добавить» → отметка первой задачи → «Удалить» этой задачи → отметка следующей задачи → и так далее по списку. Фокус не теряется и не уходит за пределы страницы.
- Enter в поле добавления отправляет форму.
- Space на отметке ставит или снимает её.
- Enter или Space на «Удалить» удаляет задачу.
- После добавления фокус остаётся в поле добавления, чтобы можно было сразу ввести следующую задачу.
- После удаления фокус переходит на «Удалить» следующей задачи; если задача была последней, на поле добавления *(предложено)*.
- Видимый фокус у каждого интерактивного элемента: заметная рамка, её нельзя убрать без замены.
- Модальных окон и ловушек фокуса нет.

## Адаптивность

- Проверка при ширине 360 px, 768 px и 1280 px.
- Горизонтальной прокрутки страницы нет ни при одной ширине.
- Длинное название переносится внутри строки и не выталкивает «Удалить» за экран.
- Кнопки и отметки удобны для касания *(предложено: область нажатия не меньше 44×44 px)*.
- При 360 px форма умещается без обрезания текста кнопки.

## Доступность

- Поле добавления имеет видимую подпись; подсказка её не заменяет.
- Каждая отметка подписана названием задачи.
- Кнопка «Удалить» имеет скрытую подпись с названием задачи, чтобы при нескольких кнопках было понятно, какая для какой задачи.
- Сообщение об ошибке связано с полем и озвучивается экранным диктором.
- Состояние отметки передаётся стандартным образом, без дополнительных пояснений.
- Контраст текста и фона не ниже WCAG AA: 4.5:1 для обычного текста, 3:1 для крупного текста и рамки фокуса.
- Признак выполнения не только зачёркивание: отметка видна без цвета и без зачёркивания.

## Что не входит

- Редактирование названия, фильтры, сортировка, пользователи, несколько списков.
- Подтверждение удаления: решено (Q1), удаление сразу.
- Перенос на другие страницы и любые экраны, кроме главной.

## Открытые вопросы

Ответы человека записываются здесь и переносятся в разделы выше. Все вопросы закрыты.

- **Q1. Удаление.** Решено: удаляем сразу, без подтверждения (ответ A).
- **Q2. Повторный клик и счётчик.** Решено: кнопка блокируется на время запроса; счётчик «Выполнено: N из M»; при пустом списке счётчик скрыт (по рекомендации, 2026-10-20).
- **Q3. Длина названия.** Пересмотрено по рекомендации: кодовые точки Unicode, как в логике.
- **Q4. Признак выполненной задачи.** Решено: зачёркивание и отметка, без дополнительного цвета (по рекомендации).
- **Q5. Путь страницы.** Решено: `/` (по рекомендации).

## Вопросы к контракту

Адресованы логическому агенту. Закрыты в `specs/001-todo-list/contract.md` (версия 1.0, 2026-10-20).

- **К1. Поля задачи.** Решено: `id`, `title`, `done`. Даты создания нет (в `AGENTS.md` её нет).
- **К2. Порядок списка.** Решено: новые задачи сверху. Логика отдаёт список от новых к старым (`id` по убыванию). UI отображает как пришло, без своей сортировки.
- **К3. Ответ после добавления.** Решено: возвращается созданная задача целиком (с `id`, `title`, `done`).
- **К4. Ответ после отметки и удаления.** Решено: отметка возвращает задачу целиком; удаление возвращает `204` без тела.
- **К5. Различаемые ошибки.** Решено: логика отдаёт код статуса и текст `error`. UI определяет состояние по коду статуса (таблица в контракте, раздел 5) и показывает свои тексты из раздела «Тексты интерфейса», текст `error` не показывает.
- **К6. Неизвестный идентификатор.** Решено: при `404` на отметку или удаление UI показывает «Задача не найдена. Обновите страницу.» и перезагружает список.
- **К7. Пробелы.** Решено: UI обрезает пробелы до отправки; сервер обрезает и проверяет то же самое.
