# Research: Список задач (UI)

**Feature**: `specs/001-todo-list/ui/spec.md` | **Date**: 2026-10-20

Внешних исследований не потребовалось: стек заранее ограничен конституцией (HTML, CSS, JavaScript без фреймворков, библиотек и сборки). Документация библиотек не нужна, поэтому context7 не вызывался.

## Decision 1: Обмен с логикой через встроенный `fetch`

- **Decision**: запросы к логике делаются встроенным `fetch` из JavaScript.
- **Rationale**: встроен в браузер, без библиотек и сборки (конституция, «Технические ограничения»).
- **Alternatives considered**: `XMLHttpRequest` (устаревший API, без выигрыша); библиотека вроде axios (запрещена стеком).

## Decision 2: Отрисовка списка без фреймворка

- **Decision**: после каждого успешного действия UI заново запрашивает `GET /api/todos` и перерисовывает список из ответа (контракт, раздел 5 и правило 8 сводки).
- **Rationale**: контракт требует именно так; список мал, лишний запрос не заметен. Один источник правды (ответ сервера) исключает расхождение с логикой.
- **Alternatives considered**: локально обновлять список по ответу `201`/`200` (быстрее, но расходится с правилом контракта); собственная реактивность (сложнее без выгоды).

## Decision 3: Блокировка кнопки «Добавить» на время запроса

- **Decision**: кнопка отключается с начала запроса добавления до ответа (решено: Q2, ответ A).
- **Rationale**: не требует идемпотентности на сервере и защищает от дубля при двойном клике.
- **Alternatives considered**: положиться на сервер (Q2, вариант B, не выбран).

## Decision 4: Сообщения об ошибках рядом с полем и в области списка

- **Decision**: сообщения выводятся текстом в области над формой или списком; блок с сообщением озвучивается экранным диктором.
- **Rationale**: соответствует разделу «Состояния» спецификации и требованию доступности.
- **Alternatives considered**: всплывающие окна (лишние фокус-ловушки, запрещены спецификацией).
