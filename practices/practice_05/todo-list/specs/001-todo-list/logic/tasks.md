# Tasks: логика todo-list

**Input**: [plan.md](plan.md), [spec.md](spec.md), [data-model.md](data-model.md), [research.md](research.md), [quickstart.md](quickstart.md). Контракт версии 1.1: [../contract.md](../contract.md).

**Prerequisites**: plan.md и spec.md обязательны. Контракт эндпоинтов не копируем: он в `../contract.md`.

**Tests**: включены. Спецификация (раздел «Проверки») перечисляет тест-кейсы для `unittest`, конституция (принцип V) требует тесты логики. TDD-порядок не обязателен, но тесты каждой фазы пишутся до реализации.

**Organization**: задачи сгруппированы по пользовательским историям из spec.md. Метки `[US1]`–`[US4]` взяты из spec.md без изменения. Инфраструктура (раздача статики, флаги, заголовки) стоит в Foundational, потому что нужна всем историям.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: можно выполнять параллельно (другой файл, нет зависимости от незавершённых задач).
- **[Story]**: история, которой служит задача (только в фазах историй).

## Path conventions

Модули в `server/`, тесты в `server/tests/`, как в `plan.md`. Страница в `static/` владеет UI; логика её только раздаёт. Все пути от корня `todo-list/`.

## Dependencies & Execution Order

### Phase dependencies

- **Setup (Phase 1)**: без зависимостей.
- **Foundational (Phase 2)**: после Setup; блокирует все истории.
- **User Stories (Phase 3–6)**: после Foundational. По приоритету: US1, US2, US4 (все P1), затем US3 (P2). US2 не зависит от US1 по коду; для проверки полного цикла нужна добавленная задача (T018).
- **Polish (Phase 7)**: после всех историй.

### Внутри истории

- Тесты до реализации.
- Хранилище (`storage.py`) до обработчика (`app.py`).
- Обработчик до ручной проверки.

### Параллельность

- T002 и T003 без `[P]`: оба в `validation.py`, выполняются подряд.
- T006 и T007 `[P]`: разные файлы (`static.py` и `test_static.py`). T010 идёт после T006.
- Тесты одной истории (`[P]`) пишутся параллельно: разные файлы.
- T035, T036, T038 — параллельно после T034.
