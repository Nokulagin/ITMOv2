# Quickstart: проверка логики todo-list

Связанные документы: [spec.md](spec.md), [plan.md](plan.md), [data-model.md](data-model.md),
[../contract.md](../contract.md) (версия 1.1).

## Требования

- Python 3.9 или новее. Внешних пакетов нет.

## Запуск тестов

Из корня проекта:

```sh
python3 -m unittest discover -s server/tests -t . -v
```

Ожидаемый результат: все тесты проходят. Тесты используют временную базу и не трогают
`data/todos.db`.

## Запуск сервера

Из корня проекта:

```sh
python3 -m server.app
```

Флаги (необязательные):

- `--port 8000` — порт, по умолчанию 8000;
- `--db data/todos.db` — путь к базе, по умолчанию `data/todos.db` от корня проекта.

Сервер слушает `127.0.0.1`, создаёт папку `data/` и таблицу, если их нет. Перед запуском проверьте,
что порт свободен.

Путь по умолчанию (`data/todos.db`) считается от корня проекта. Явный относительный путь в `--db`
считается от текущей папки запуска.

## Проверка страницы

Откройте в браузере `http://127.0.0.1:8000/`. Страница из `static/` отдаётся с кодом 200.
Проверка через curl:

```sh
curl -s -i http://127.0.0.1:8000/ | head -n 1
# ожидается: HTTP/1.0 200 OK
curl -s -i http://127.0.0.1:8000/static/no-such-file.css | head -n 1
# ожидается: HTTP/1.0 404 Not Found
```

Пока `static/` не создан (это задача UI), `GET /` вернёт 404. Это ожидаемо до появления страницы.

## Ручная проверка API через curl

Предполагается, что сервер запущен на `http://127.0.0.1:8000`.

```sh
# 1. Список пустой
curl -s http://127.0.0.1:8000/api/todos
# ожидается: []

# 2. Добавление: 201 и задача с done=false
curl -s -i -X POST http://127.0.0.1:8000/api/todos \
  -H 'Content-Type: application/json' \
  -d '{"title": "  Купить молоко  "}'
# ожидается: 201, title "Купить молоко", done false

# 3. Пустое название: 400
curl -s -X POST http://127.0.0.1:8000/api/todos \
  -H 'Content-Type: application/json' -d '{"title": "   "}'
# ожидается: {"error": "Название задачи не может быть пустым."}

# 4. Отметка: 200 и done=true (подставьте id из шага 2)
curl -s -X PATCH http://127.0.0.1:8000/api/todos/1 \
  -H 'Content-Type: application/json' -d '{"done": true}'

# 5. Неизвестный id: 404
curl -s -i -X PATCH http://127.0.0.1:8000/api/todos/999 \
  -H 'Content-Type: application/json' -d '{"done": true}'

# 6. Удаление: 204 без тела
curl -s -i -X DELETE http://127.0.0.1:8000/api/todos/1

# 7. Список снова пустой
curl -s http://127.0.0.1:8000/api/todos
```

## Проверка заголовков (411 и 400)

```sh
# 8. Тело без Content-Length: 411
curl -s -i -X POST http://127.0.0.1:8000/api/todos \
  -H 'Content-Type: application/json' -H 'Transfer-Encoding: chunked' \
  -d '{"title": "x"}'
# ожидается: 411, {"error": "Требуется заголовок Content-Length."}
```

## Что проверить глазами

- Новые задачи в списке идут сверху (порядок `id` по убыванию).
- Тело больше 4096 байт даёт 413, и следующий запрос на сервере работает.
- Ответы с ошибками содержат поле `error` на русском, без текста исключения.
- Сервер слушает только `127.0.0.1`.
