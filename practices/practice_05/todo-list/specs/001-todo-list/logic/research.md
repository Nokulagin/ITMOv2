## 1. Соединение с базой: закрывать явно

**Decision**: каждая операция открывает соединение `sqlite3.connect(...)`, делает транзакцию и
закрывает соединение явно (`try/finally` или `contextlib.closing`).

**Rationale**: по документации 3.9, соединение как контекстный менеджер (`with con:`) только
коммитит при успехе и откатывает при ошибке. Оно не закрывает соединение: «the connection itself
must still be closed manually». Без явного закрытия файл останется открытым до сборки мусора.

**Alternatives considered**:
- Одно соединение на процесс: отвергнуто (решение 10 контракта, и с однопоточным сервером не даёт
  выигрыша).
- `with sqlite3.connect(...) as con:` без закрытия: отвергнуто, утечка соединения.

## 2. Сервер однопоточный

**Decision**: `http.server.HTTPServer`, а не `ThreadingHTTPServer`.

**Rationale**: по документации `HTTPServer` обрабатывает запросы последовательно; `ThreadingHTTPServer`
использует потоки. Решение человека (Clarifications, сессия 2026-10-20): один запрос за раз.
Параллельные записи в SQLite не возникают, блокировки не нужны.

**Alternatives considered**: `ThreadingHTTPServer` с защитой записей: отвергнуто как избыточное
для учебного проекта с одним клиентом.

## 3. Отказ по размеру тела (413) с однопоточным сервером

**Decision**: при `Content-Length` больше 4096 байт ответ 413 отправляется без чтения тела, и
соединение помечается на закрытие (`close_connection = True`).

**Rationale**: не читать тело больше лимита, чтобы не держать однопоточный сервер на большом запросе.
Остаток непрочитанного тела иначе попадёт в начало следующего запроса на том же соединении
(HTTP/1.1 keep-alive), поэтому соединение закрывается.

**Alternatives considered**: читать тело до конца и потом отвечать 413: отвергнуто, это нагрузка
на однопоточный сервер ради ответа, который клиент всё равно не использует.

**Проверка**: поведение после 413 и следующий корректный запрос проверяются в `test_api.py`.

## 4. Нечисловой `id` в пути

**Decision**: `id` из пути разбирается как целое число; если не получилось или `id <= 0`, ответ 404
«Задача не найдена.», как для неизвестного `id` (контракт, раздел 4).

**Rationale**: контракт относит нечисловой `id` к 404, а не к 400.

## 5. Порядок списка

**Decision**: `ORDER BY id DESC` (новые сверху), как в контракте, раздел 6.

**Rationale**: решение человека, UI-вопрос 3 (ответ B). Сортировку на стороне UI не делаем.

## 6. Запрос без `Content-Length` (411) и некорректный заголовок (400)

**Decision**:
- если в запросе есть тело, но нет заголовка `Content-Length`, или есть `Transfer-Encoding`
  (в том числе `chunked`), ответ 411 «Требуется заголовок Content-Length.»;
- если `Content-Length` не разбирается как целое число или отрицательный, ответ 400
  «Некорректный заголовок Content-Length.».

**Rationale**: контракт 1.1, раздел 3 и 4. Порядок проверок в `PATCH`: сначала заголовок и размер
(400, 411, 413), затем тело (400), затем `id` в базе (404).

**Alternatives considered**: читать тело до конца без `Content-Length`: отвергнуто, однопоточный
сервер не знает, сколько читать. Чтение `chunked` не поддерживаем: контракт требует 411.

## 7. Раздача статики: `mimetypes` и защита пути

**Decision**: `GET /` отдаёт `static/index.html`. `GET /static/{имя}` отдаёт файл из `static/`.
Тип берётся из `mimetypes.guess_type`, для `.css` и `.js` задаётся `charset=utf-8` явно, как в
контракте (раздел 10). Путь нормализуется через `pathlib`; если результат выходит за `static/`
или содержит `..`, или файла нет, ответ 404 «Маршрут не найден.».

**Rationale**: `mimetypes.guess_type(url)` по документации 3.9 возвращает `(тип, кодировка)` по имени
файла. Кодировку для текстовых типов задаёт контракт, поэтому её не берём из `guess_type`.

**Alternatives considered**: отдавать файлы через `SimpleHTTPRequestHandler`: отвергнуто, он раздаёт
текущий каталог и ломает правило 404 из контракта для путей вне `static/`.

## 8. Флаги запуска

**Decision**: `argparse` с флагами `--port` (`type=int`, по умолчанию 8000) и `--db` (по умолчанию
`data/todos.db` от корня проекта). Сервер слушает `127.0.0.1`.

**Rationale**: контракт 1.1, раздел 10. `type=int` даёт понятную ошибку на нечисловой порт.
