# Data model: логика todo-list

Источник правил: [spec.md](spec.md), раздел «Данные» и «Правила»; формат JSON: [../contract.md](../contract.md), раздел 2.

## Таблица `todos`

| Колонка | Тип SQLite | Ограничения | Примечание |
|---|---|---|---|
| `id` | INTEGER | `PRIMARY KEY AUTOINCREMENT` | назначает база; не переиспользуется после удаления |
| `title` | TEXT | `NOT NULL` | после обрезки от 1 до 200 кодовых точек (проверка в `validation.py`) |
| `done` | INTEGER | `NOT NULL DEFAULT 0` | 0 или 1; в JSON передаётся как `false`/`true` |

Схема создаётся при старте командой `CREATE TABLE IF NOT EXISTS`, без миграций (спецификация,
раздел «Что не входит»).

## Преобразования

- Запись: `title` уже обрезан и проверен; `done` = 0 при создании.
- Чтение: строка `(id, title, done)` превращается в объект `{"id": id, "title": title, "done": bool(done)}`.
- `done` в запросе принимается только как логическое значение JSON (`true`/`false`). Число `1` и строка
  `"true"` отклоняются с 400 (спецификация, «Правила»).

## Правила полей (из спецификации)

| Поле | Правило | Где проверяется |
|---|---|---|
| `title` | строка; после обрезки пробелов и переводов строк длина 1–200 кодовых точек | `validation.py` |
| `done` | `true` или `false` | `validation.py` |
| `id` (путь) | целое число больше 0; иначе 404 | `app.py` |

Длина считается в кодовых точках Unicode, не в байтах: 200 кириллических букв проходят, 201 нет.

## Состояния

Состояний у задачи два: `done = 0` и `done = 1`. Переходы свободные: отметить можно повторно,
снять отметку можно у любой задачи. Удаление физическое, строка уходит из таблицы.
