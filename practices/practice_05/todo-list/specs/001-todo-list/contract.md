## 1. Общие правила

- Адреса: тот же origin, что и страница. API живёт по путям `/api/todos`. Страница и статика
  описаны в разделе 10.
- Формат: JSON в UTF-8. Запросы с телом отправляют `Content-Type: application/json` и обязательно
  `Content-Length` (раздел 4, код 411). Ответы с телом отдают `application/json`.
- Тексты поля `error` на русском. UI их не показывает пользователю: он выбирает свой текст по
  коду статуса (раздел 5).
- Название задачи: пробелы и переводы строк по краям убираются; длина считается в кодовых точках
  Unicode после обрезки (раздел 6).
- Лимит тела запроса: 4096 байт.

## 2. Модель задачи

| Поле | Тип JSON | Ограничения | Примечание |
|---|---|---|---|
| `id` | integer | больше 0 | назначает сервер; не переиспользуется после удаления (`AUTOINCREMENT`) |
| `title` | string | от 1 до 200 кодовых точек после обрезки | |
| `done` | boolean | `true` или `false` | по умолчанию `false` |

Пример: `{"id": 1, "title": "Купить молоко", "done": false}`

Дат создания и обновления нет (в `AGENTS.md` их нет).

## 3. Эндпоинты

| Операция | Метод и путь | Тело запроса | Успех | Возможные ошибки |
|---|---|---|---|---|
| Список | `GET /api/todos` | нет | `200`, массив задач, новые сверху | `500` |
| Добавить | `POST /api/todos` | `{"title": "строка"}` | `201`, созданная задача | `400`, `411`, `413`, `500` |
| Отметить или снять отметку | `PATCH /api/todos/{id}` | `{"done": true}` или `{"done": false}` | `200`, задача целиком | `400`, `404`, `411`, `413`, `500` |
| Удалить | `DELETE /api/todos/{id}` | нет | `204`, без тела | `404`, `500` |

Порядок проверок в `PATCH`: сначала заголовок `Content-Length` и размер тела (`400`, `411`, `413`),
затем тело (`400`), затем наличие `id` в базе (`404`). Неверное тело на несуществующей задаче
даёт `400`.

Неизвестный путь даёт `404` с текстом «Маршрут не найден.». Неподдерживаемый метод даёт `405`.

## 4. Коды ошибок

Формат тела ошибки: `{"error": "текст на русском"}`.

| Код | Когда | Текст `error` |
|---|---|---|
| 400 | заголовок `Content-Length` не число или отрицательный | `Некорректный заголовок Content-Length.` |
| 400 | тело не JSON или не объект | `Тело запроса должно быть JSON-объектом.` |
| 400 | `title` отсутствует или не строка | `Название задачи должно быть строкой.` |
| 400 | `title` пустое после обрезки | `Название задачи не может быть пустым.` |
| 400 | `title` длиннее 200 кодовых точек | `Название задачи не должно быть длиннее 200 символов.` |
| 400 | `done` отсутствует или не логическое значение | `Поле done должно быть true или false.` |
| 404 | `id` не найден или не число | `Задача не найдена.` |
| 404 | неизвестный путь или файл статики | `Маршрут не найден.` |
| 405 | метод не поддерживается для пути | `Метод не поддерживается.` |
| 411 | запрос с телом без `Content-Length` (в том числе `Transfer-Encoding: chunked`) | `Требуется заголовок Content-Length.` |
| 413 | тело больше 4096 байт | `Тело запроса слишком большое.` |
| 500 | ошибка базы данных | `Внутренняя ошибка сервера.` |

Ошибка `500` не раскрывает детали клиенту (путь к файлу, текст исключения); детали пишутся в
журнал сервера.

Правила UI, связанные с контрактом:

- Кнопка «Добавить» блокируется на время запроса добавления; повторный клик не создаёт дубль.
- После каждой успешной операции UI запрашивает `GET /api/todos` заново.
- UI не ставит `maxlength` на поле названия: иначе сообщение о 201 символе не появится.

## 6. Порядок списка, длина, лимиты и приоритеты

- **Порядок**: по убыванию `id`, то есть новые задачи сверху. UI не сортирует список сам.
- **Длина названия**: считается в кодовых точках Unicode после обрезки пробелов. UI считает так же,
  например через `[...строка].length`. Эмодзи из нескольких кодовых точек считаются как несколько
  символов. Байты не считаем.
- **Обрезка**: и UI, и сервер убирают пробелы и переводы строк по краям. Внутренние не меняются.
- **Лимит тела**: 4096 байт, проверяется до разбора JSON.
- **Загрузка**: один запрос `GET /api/todos` без пагинации.
- **Идентификаторы**: `AUTOINCREMENT`; после удаления новая задача получает больший `id`.
- **Приоритеты историй** (одни для обеих спецификаций): US1 (добавление), US2 (отметка) и US4
  (загрузка) — P1; US3 (удаление) — P2.

## 10. Размещение файлов, раздача страницы, запуск и тесты

**Размещение** (корень проекта `todo-list/`):

- `server/` — бэкенд, владелец логика: `app.py` (точка входа и маршруты), `storage.py`,
  `validation.py`, `tests/`.
- `static/` — страница, владелец UI: `index.html`, `styles.css`, `app.js`.
- `data/` — база `data/todos.db`, создаётся при старте, в git не попадает.

**Раздача страницы** (отвечает сервер логики):

- `GET /` → `static/index.html`, `200`, `Content-Type: text/html; charset=utf-8`.
- `GET /static/{имя}` → файл из `static/`, `200`. `.css` отдаётся как `text/css; charset=utf-8`,
  `.js` — как `text/javascript; charset=utf-8`.
- Файла нет, путь содержит `..` или выходит за `static/` → `404`, текст «Маршрут не найден.».
- `index.html` подключает `/static/styles.css` и `/static/app.js`. Внешних ресурсов нет.

**Запуск**: `python3 -m server.app`. Флаги:

- `--port` — порт, по умолчанию `8000`;
- `--db` — путь к базе, по умолчанию `data/todos.db` от корня проекта.

Сервер слушает `127.0.0.1`.

**Тесты**: одна команда из корня проекта: `python3 -m unittest discover -s server/tests -t . -v`.
