# AGENTS.md

## Проект

Todo-list: одна страница, список задач хранится в базе данных (SQLite).
Учебный проект для ДЗ5 курса: две спецификации (UI и логика), согласованный контракт, затем код.

## Фреймворк

Спецификации пишем по **GitHub Spec Kit** (`specify` уже установлен). Использовать другой SDD-фреймворк нельзя, OpenSpec тоже.

## Статус

Фаза: обсуждение задач. Спецификаций и кода пока нет. Решения ниже предварительные и уточняются с человеком.

## Порядок работы

1. Обсуждаем задачи каждого агента с человеком. Спеки на этом шаге не пишем.
2. Человек утверждает задачи.
3. Агенты пишут свои спецификации по Spec Kit.
4. Обсуждаем итоговый контракт с человеком.
5. Только после согласования контракта пишем код.

## Что делаем

- добавить задачу: название от 1 до 200 символов;
- отметить задачу выполненной и снять отметку;
- удалить задачу;
- список хранится в SQLite-файле `data/todos.db`.

Не входит в проект: редактирование названия, фильтры, сортировка, пользователи, несколько списков.

## Стек (предварительно)

- Бэкенд: Python 3, только стандартная библиотека (`http.server`, `sqlite3`). Пакеты через pip не ставим.
- Фронтенд: HTML, CSS и JavaScript без фреймворков и сборки.

## Структура

```
todo-list/
  AGENTS.md          этот файл: общие правила и описание проекта
  agents/            инструкции для агентов по ролям
    ui-agent.md      роль: UI-спецификация
    logic-agent.md   роль: логическая спецификация
  .mcp.json          MCP-сервер context7 (актуальная документация библиотек)
  .specify/          Spec Kit: конституция в memory/, шаблоны, скрипты
  specs/
    001-todo-list/   одна фича; появляется после обсуждения
      ui-spec.md     спецификация UI (агент UI)
      logic-spec.md  спецификация логики (агент логики)
      contract.md    общий контракт, меняется только с согласия человека
```

## Правила для всех агентов

- Язык: спецификации и текст для человека на русском. Код, имена, комментарии в коде на английском.
- Фреймворк: GitHub Spec Kit.
- Сейчас обсуждаем задачи и не создаём файлы спецификаций, пока человек не скажет.
- Агент правит только свой файл спецификации. Чужой файл не трогаем.
- Вопросы к другой стороне записываем в раздел «Вопросы к контракту» своего файла.
- `specs/contract.md` меняет только человек или агент по его прямому согласию.
- Решения принимает человек. Агент предлагает варианты и рекомендацию.
- Перед работой прочитай этот файл и свою роль в `agents/`.
- Документацию библиотек и фреймворков всегда берём через MCP-сервер `context7`, а не из памяти модели. Если context7 недоступен, так и пишем человеку, а не угадываем API.
- Все работают в одной ветке `2026_Nokulagin_practice_5`. Ветки под спеки не создаём.
