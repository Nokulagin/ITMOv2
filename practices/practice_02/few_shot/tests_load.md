# Нагрузочные проверки

Цели и SLO:
- p95 ≤ 10 с для успешных запросов при целевой нагрузке.
- p99 ≤ 12 с для успешных запросов при целевой нагрузке.
- Доля ошибок в steady‑state ≤ 1% (исключая ожидаемые 413 для >20k по API‑1).
- Для входов > 20 000 символов — 100% HTTP 413 (API‑1).
- При срабатывании таймаута внешнего LLM (10 с) — 100% контролируемых ответов без падений (REL‑1).

Если нагрузочное тестирование пока не требуется, обоснуйте это и назовите условие, после которого оно понадобится.

Политика запуска:
- Не требуется: локально, < 2 RPS, без CI.
- Обязательно: CI с параллельными ревью (≥ 5 RPS); прод; изменения, затрагивающие API‑1 (порог 20k), REL‑1 (таймаут 10 с), SEC‑1 (редакция секретов), OBS‑1 (логирование); рост p95/error rate по мониторингу.

## Методика

- Разогрев: перед измерениями 1–2 мин при 1 RPS для стабилизации.
- Генерация входов:
  - Валидные diff: используем TRAINING_PR.diff как основной вход.
  - Сверхлимитные: конструируем diff длиной > 20 000 символов (например, дублированием фрагментов) для проверки 100% 413 (API‑1).
  - Синтетические секрет‑паттерны: добавляем безопасные шаблоны (например, `token=...`, `-----BEGIN PRIVATE KEY-----`) и проверяем, что перед внешним LLM они заменены на `[REDACTED]` (SEC‑1).
- Стабильность стенда: фиксируем версии, один источник нагрузки, отсутствие параллельных фоновых тестов.
- Повторяемость: не менее 3 прогонов каждого сценария; сохраняем конфиг/план, seed/данные генерации и commit hash.
- Инструменты: допустимы k6/JMeter/Locust; фиксируем версии инструмента и сценарии.
- Подсчёт метрик: p50/p95/p99 считаются по успешным ответам; 413 и таймауты считаются отдельно; error rate — доля неуспехов в steady‑state.
- Наблюдаемость и соответствие OBS‑1: проверяем, что в логах только `request_id`, длительность и статус; diff/ответ модели не логируются.

## Приёмка

- Автоматизируемые проверки порогов: билд/джоб падает при нарушении SLO/SLA таблицы.
- Проверки правил:
  - >20k символов → 100% HTTP 413 (API‑1) — выборка ответов подтверждает.
  - Таймаут внешнего LLM (10 с) → 100% контролируемых ответов, 0 5xx (REL‑1).
  - Отсутствие утечек секретов: при подмешанных секрет‑паттернах в prompt перед внешним LLM — `[REDACTED]`; в логах нет содержимого diff/ответа; только разрешённые поля (SEC‑1, OBS‑1).
- Отчётность: прикладываем экспорт метрик (.json/.csv), графики p50/p95/p99 и кодов, конфиг сценариев/данных, seed, версии инструментов, commit hash и ссылку на артефакты CI.
