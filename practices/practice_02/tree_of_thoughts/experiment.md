# Tree of Thoughts

- Решение, для которого нужны альтернативы: как минимально и проверяемо переписать `tests_load.md` до уровня Практики 2.
- Критерии выбора: Consistency (SEC‑1/API‑1/REL‑1/OBS‑1/OUT‑1), Verifiability (проверяемые пороги/evidence), Reproducibility (профили/RPS/длительность/прогрев/повторы), Minimality (минимальность правок и сохранение структуры).

## Запрос
Промпт ToT для улучшения tests_load.md:

```
Роль
Ты — инженер по производительности. Применяешь Tree of Thoughts (ToT) для минимального и проверяемого улучшения файла tests_load.md до уровня Практики 2.

Источники (только эти)
- practices/practice_01/tests_load.md — исходник (см. во входе ниже)
- CASE.md
- context.md (Context Pack)
- README.md (по процессу)
- Внешние источники запрещены. prompts.md используем только как справочник формата, не как источник фактов.

Ограничения и правила Context Pack
- SEC-1: секреты перед внешним LLM редактируются до [REDACTED]; утечек быть не должно.
- API-1: diff > 20 000 символов → 100% HTTP 413.
- REL-1: таймаут внешнего LLM 10 с; ошибки конвертируются в контролируемый ответ; сервис не падает.
- OBS-1: логируются только request_id, длительность, статус; запрещено логировать diff/ответ модели.
- OUT-1/QA-1: включать только подтверждённые утверждения и пороги с evidence.
- Минимизируй изменения: сохрани заголовки и стиль, расширяй содержимое.

Цель улучшения
Сделать артефакт воспроизводимым и проверяемым:
- Цели и SLO: p95 ≤ 10 с; добавить p99 (например, ≤ 12 с); error rate ≤ 1%; 100% 413 для >20k; 100% контролируемых таймаутов.
- Сценарии: база (ramp→steady), отказ >20k (API‑1), таймаут LLM 10 с (REL‑1), burst, soak, конфиденциальность/логи (SEC‑1/OBS‑1).
- Методика: прогрев, ≥3 прогона, генерация входов (валидные/сверхлимитные/секрет‑паттерны), мок внешнего LLM, стабильность стенда, инструменты (k6/JMeter/Locust).
- Приёмка и evidence: автопроверки порогов, экспорт метрик/графики в CI, проверка логов.
- Политика запуска: когда не требуется и когда обязательна (CI ≥ 5 RPS; прод; изменения API‑1/REL‑1/SEC‑1/OBS‑1; деградации).

Tree of Thoughts — процесс и критерии
- Декомпозиция на секции: «Цели и SLO», «Сценарии», «Методика», «Приёмка и evidence», «Политика запуска».
- Для каждой секции сгенерируй 3 краткие альтернативы (мысли/подходы), не более 2–3 предложений каждая.
- Оцени каждую альтернативу по шкале 0–3 по четырём критериям:
  1) Consistency: соответствие SEC‑1/API‑1/REL‑1/OBS‑1/OUT‑1.
  2) Verifiability: наличие проверяемых порогов/evidence.
  3) Reproducibility: воспроизводимость (профиль нагрузки, RPS, длительность, прогрев, повторы).
  4) Minimality: минимальность правок и сохранение структуры.
- Выбери по одной лучшей альтернативе на секцию (суммарный балл, при равенстве — более строгая по правилам).
- Разрешение конфликтов: выигрывает более строгая формулировка, согласованная с правилами Context Pack.
- Глубина дерева: 2 уровня (альтернативы → выбор). Не уходи в скрытые рассуждения; выводи только наблюдаемые альтернативы и их оценки.

Остановка
- Остановись, когда для каждой секции выбрана лучшая альтернатива и нет конфликтов с правилами.
- Если контекст недостаточен, пометь «Требуется решение команды» вместо выдуманных чисел/фактов.

Формат результата (строго)
1) Alternatives & Scores — для каждой секции: A/B/C, оценки (Consistency/Verifiability/Reproducibility/Minimality), Total, Выбранная.
2) Selection Rationale — 1–2 предложения на секцию.
3) Final tests_load.md — финальный Markdown файл.
4) Changes — краткий список правок.
5) Rejected — отклонённые альтернативы с 1 причиной.
6) Sources — 3–6 маркеров: [file: секция/правило, цитата/порог].

Вход (вставь текущее содержимое tests_load.md)
```
